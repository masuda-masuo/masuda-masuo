# Hi there, I'm masuda-masuo 👋

**AI-Native Infrastructure Builder / Developer**

AIエージェント（LLM）が自律動作し、人間と共生してソフトウエアを構築する時代における、「Agent Experience (AX)」に最適化された安全で堅牢なAI専用インフラ・ツールチェインの開発を行っています。

作っているものは一見バラバラですが、芯にあるのは一つです。**LLMにとってコンテキストは有限資源であり、性能を決めるのは「何を渡すか」ではなく「何を渡さないか」**。プロンプトによる指示（賢さ）に頼る設計には限界があるので、その境界をインフラ側で構造的に引きます。

*   🏜️ **[sunaba](https://github.com/masuda-masuo/sunaba)** — ペイロード（ソース・差分・生ログ）を**LLMに通さない**
*   🔖 **[shiori](https://github.com/masuda-masuo/shiori)** — 全文ではなく**ポインタを返す**
*   🪓 **[kusabi](https://github.com/masuda-masuo/kusabi)** — ワーカーの中間出力を**親エージェントに届かせない**

## 🛠️ Project Portfolio

### 1. [sunaba (砂場)](https://github.com/masuda-masuo/sunaba) 🏜️
> **Less context. Less trust. More structure.** — フロンティアLLM向けに最適化された開発MCP

*   **モデルは有能である前提に立つ**: 大半のAI開発ツールは「ターミナルを見ている人間」を中心に設計されています。sunaba は「小さく構造化されたコンテキストの上で推論するモデル」を中心に据え、手取り足取りの巨大なツール群ではなく、少数の一級の動詞（search / edit / verify / publish）と、モデルが既に知っているCLI群を渡します。
*   **渡さないことが価値**: Issue本文・ソース・差分・生ログといった重いデータはコンテナ内で生まれてコンテナ内で死に、モデルが運ぶのは `run_id` とハンドル、構造化サマリだけ。テスト結果は緑なら1行、失敗は5000行のログではなく `{test, error, file, line}` で返ります。
*   **信頼は方針ではなく構造で**: 「危険なコマンド」をフィルタする方式は採りません。守るのは**サンドボックスの境界**だけです。ホストは構成上切り離され、VCSトークンはホスト側に留まり**コンテナには一切渡りません**。だからこそAIクライアント側の広範なホスト実行権限を*切る*ことができます。
*   **検証ゲート**: lint・型チェック・テストを完全にパスしない限り提出（`publish`）を認めません。使い捨てDockerコンテナの中で test → verify → publish のループが丸ごと回ります。パニックループを止める「Undoタイムマシン（`undo_file_edit`）」やトークン不要のセーブポイント（`checkpoint`）も標準装備。

### 2. [shiori (栞)](https://github.com/masuda-masuo/shiori) 🔖
> **プロジェクトの「Why」への導線を返す、ポインタ型の知識検索MCP**

*   **狙いは「Why」**: What と How は main ブランチのコードとドキュメントにあり、cloneしてしまえば grep で読めます。しかし**なぜその設計になったか・何が却下されたか・どんな罠が既知か**は Issue と PR のスレッドにしか無く、GitHub 検索は意味検索でもクロスリンガルでもないため、AIエージェントには事実上到達不能です。ここを埋めるのが shiori の本体です。
*   **RAGではない**: 回答を生成せず、コンテキストへの自動注入もしません。返すのは**座標とスニペット（ポインタ）だけ**で、全文を読むかどうかはエージェントが決める **Pointer-then-Fetch** モデル。検索結果自体がコンテキストを食い潰すのを防ぎます。
*   **境界を越えて辿れる**: ドキュメント・コード・Issue/PR議論を**単一の索引**に載せ、同一のランキングで返します。ヒットしたIssue → 解決したPR → 変更されたファイル → 設計文書、と種類の壁を越えて連鎖的に辿れる。日本語のクエリで英語のIssueが引けます。
*   **アーキテクチャ**: GitHub APIの中継プロキシではなく、ローカルの PostgreSQL（`pgvector` + `pgroonga`）と Shallow Clone によるローカルデータストア。ベクトルとキーワードを RRF で融合し、埋め込みモデルもローカルで動くため**完全オフライン**。人間向けのブラウザダッシュボードを同梱しています。

### 3. [kusabi (楔)](https://github.com/masuda-masuo/kusabi) 🪓
> **コンテキストファイアウォールとしての委譲オーケストレーション**

*   **委譲の価値は「安さ」ではない**: 重い実装や調査を別のエージェントに投げる本当の理由は、**ワーカーの中間出力（ナレーション、ツールログ、生イベント）が親のコンテキストを焼かないこと**です。それらは全てローカルの状態ディレクトリに永続化され、親には**レンダリング済みの最終結果だけ**が返ります。バックエンドは [opencode](https://opencode.ai) が既定、`--backend claude` でヘッドレスな Claude Code CLI も選べます。
*   **独立コンテキストによる敵対レビュー**: 実装したモデルに自分の仕事をレビューさせても意味がありません。**別セッションの独立したエージェント**にレビューさせ、「**実装 ➔ レビュー ➔ 差し戻し**」を受理か打ち切りまで自動で往復させます（`chain`）。ラウンドが進むごとにモデル階層を上げる段階的エスカレーション付き。安価なモデルでも、独立したコンテキストであることそれ自体が検出力を生みます。
*   **経済的打ち切り**: テストが全緑で残る指摘が軽微なら、そこでループを打ち切って合格とし、残作業をフォローアップIssueの下書きへ繰り延べます。早期終了の悪用は、独立レビュー・機械テストの絶対性・Issueの可視化という多重ゲートで抑えます。
*   **死に方も設計する**: ワーカーがクラッシュやタイムアウトで死んだ際に直前のログから事故原因を自動調査する「**自律サルベージ（`salvage`）**」、実装セッションからホスト側の書き込みツールを構造的に剥奪するフェーズ別のパーミッション制御を装備。
